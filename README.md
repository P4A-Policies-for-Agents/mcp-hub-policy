# mcp-hub-policy

A custom **MuleSoft Omni Gateway / Flex Gateway** policy that turns one
governed API into a **virtual MCP aggregation endpoint**. AI agents and
MCP clients see a single `/mcp` endpoint; the policy orchestrates calls
to every configured upstream MCP server, merges manifests, applies
per-server auth, and routes tool / resource / prompt invocations to the
owning upstream.

Built with [PDK 1.8](https://docs.mulesoft.com/pdk/latest/policies-pdk-overview)
(Rust → WASM). Closest reference: the
[`acp-to-a2a`](../acp-policies/acp-to-a2a) bridge.

## Build

Prerequisites: Rust 1.88, `cargo-anypoint` 1.8, `anypoint-cli-v4`
(authenticated via `anypoint-cli-v4 conf` / `make login`).

```sh
make setup    # one-time: installs cargo-anypoint, fetches deps
make build    # builds wasm + definition + implementation YAMLs
make test     # runs cargo unit + integration tests
make run      # starts a local Flex Gateway with the policy applied
make publish  # publishes a development version to Anypoint Exchange
make release  # publishes a release version
```

`make build` regenerates `src/generated/config.rs` from
`definition/gcl.yaml`. Do not edit it by hand — change the GCL.

## Quick demo (no Anypoint required)

```sh
# Run a local Flex with two upstream MCP servers configured.
make run
# In another shell, talk MCP to the hub:
curl -s http://localhost:8081/mcp \
  -H "content-type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | jq .
```

The default `playground/config/api.yaml` points at two placeholder
upstreams; replace them with real MCP server URLs to see actual
aggregation. See `definition/home.md` for the full configuration
reference.

## Method dispatch

| MCP method        | Where it's handled                         |
|-------------------|--------------------------------------------|
| `initialize`      | Local handshake — hub identifies itself    |
| `ping`            | Local 200                                  |
| `tools/list`      | Aggregate across all enabled upstreams     |
| `tools/call`      | Route to the upstream owning the tool name |
| `resources/list`  | Aggregate                                  |
| `resources/read`  | Route                                      |
| `prompts/list`    | Aggregate                                  |
| `prompts/get`     | Route                                      |
| `notifications/*` | Fan out to every upstream best-effort      |

## Collision handling

`collisionStrategy` (default `prefix`) controls what happens when two
upstreams declare the same tool / resource / prompt name. With `prefix`
the hub renames inbound to `<server>.<name>` and rewrites outbound to
the original name when routing — clients see disambiguated names,
upstreams see their native namespaces.
